# The browser prototype: technical debt

Items owed on the browser when it moved out of the engine on 16 October 2026 (REQUIREMENTS.md decision E.76), carried over from the engine's `TECH-DEBT.md` as they stood. Paths are as they were before the move: `crates/neoteletext-gui` is now `prototypes/browser/crates/neoteletext-gui`, `tests/web-server/sites.py` is `prototypes/browser/tests/sites.py`, and the REQ-BRW requirements are in `docs/requirements.md` here.

- **`tests/fonts.rs` and some window tests do not compile or match** (see below), and the prototype is outside the engine's gates: run `cargo test --workspace` here before relying on it.

- **Embedded fonts and one font dropdown** (owner, 14 October 2026: "embed all the complete and conforming 12x10 fonts into the program for testing … drop the functionality for a font per character set and just have a single font dropdown … gate the NONFREE fonts behind a feature which is enabled by default"). `crates/neoteletext-gui/build.rs` reads the font tree's `catalog/complete-fonts.tsv` (`$NEOTELETEXT_FONT_TREE`, or `~/devel/teletext-reference/teletext-fonts`) and compiles its fonts in as glyph tables (`src/embedded.rs`); open fonts always, the rest with the default feature `nonfree-fonts`. Seven fonts today (bedstead-complete, zvbi-wstfont2-all-sets, hisilicon-histb-completed, philips-complete, realtek-rtd2668-all-sets-sa, siemens-itt-micronas-sda55xx-completed, texas-instruments-eurotext-completed). The toolbar has one dropdown, Bedstead first and the default, saved as `embedded_font`; the chosen font draws every set. "Character rounding" moved to the Menu. This supersedes the fonts panel (#215) and the font switcher below: `app/font_browser.rs` and `app/font_switcher.rs` are deleted (copies in the session scratchpad), and with them the per-set choice, the library fetching from the browser's interface and the arrow-key stepping. Owed:
  - the owner's decision whether this is for testing only or replaces REQ-BRW-010 and the libraries of area FNT; a Part E decision either way, and whether a release build may embed non-free fonts at all (it must not ship them; `--no-default-features` builds the open ones only);
  - the LGPL: zvbi's font is embedded as an open font, against CREDITS.md's rule that it stays loadable only; the owner to confirm, or exclude it from the embedded list;
  - the build reads files outside the repository, so a build depends on the machine; REQ-TST-022's pinning by checksum is not applied (the list carries each font's SHA-256; build.rs does not check it);
  - `cargo build -p neoteletext-browser` does not rerun the gui crate's build script; build `-p neoteletext-gui` after the list changes;
  - `tests/fonts.rs` no longer compiles (`update_tab` now takes the tab and the settings only); window tests in `tests/window.rs` for the panels (`the_font_browser`, `the_font_settings`, `the_font_switcher_steps_with_the_arrow_keys`) are now stale; replace with a test of the dropdown, its saving, and rounding with an embedded font;
  - `fonts.rs` still carries the decoder's per-set machinery (`DecoderFonts.by_set`) unused by the interface; remove or keep per the decision;
  - the Developer tools "Character sets" tab now names the embedded font for every set;
  - the user guide, ARCHITECTURE.md (build-time input to L9), the log row.
  - **Row 0 follows the page** (owner, 14 October 2026: "Should the header follow the page? YES"): `picture.rs` `overlay_row0` draws the header in the chosen embedded font with the rounding switch (`Look`); the receiver's own pages stay in Bedstead. Row 0 columns 0 to 7 are still drawn by the receiver alone, only in the page's font. Owed: amend REQ-FNT-001 and REQ-FNT-005 (the receiver's drawing always in Bedstead) and decision E.72 for the header; a window test that the header changes with the font and the switch.
  - **Half-dot fonts are not rounded** (owner, 14 October 2026, after the survey below: "do as you recommend"). Rounding a loaded font that is not a doubled dot matrix was tried and withdrawn: every decoder with a 12 x 10 font showed it as drawn, the designs carry their own smoothing, and the rule changed 15 of zvbi's 96 Latin glyphs while adding almost nothing to Philips complete. `render.rs` is back to rounding only doubled dot matrices (issue #209). The Menu's "Character rounding" switch is greyed out when the chosen font is drawn at half-dot resolution, with a tooltip saying why (`embedded::rounds`). Owed: a Part E decision recording the choice and the survey (rounding a half-dot font is not done by any hardware at normal size; Philips SAA56xx smoothed only enlarged characters, an option to try later); a window test of the greyed switch.
  - **Survey of rounding implementations** (14 October 2026, about 135 implementations: emulators, FPGA cores, teletext software, chips, patents). E.13 is confirmed identical to the SAA5050 (datasheet, decap, BeebFpga, MAME, jsbeeb, B2, BeebEm's font, edit.tf, Bedstead), including double height and edges. No hardware or software rounds a 12 x 10 half-dot font at normal size: Philips SAA56xx smooths only enlarged characters and also fills L-shaped corners (US4796016A); ST ST92195 uses the strict rule at half a font pixel; zx84's shader is the only software precedent. So rounding loaded half-dot fonts is a project choice, to be recorded as such in Part E. The three reports are in the session scratchpad (`rounding-hardware.md`, `rounding-software.md`, `rounding-emulators.md`); owed: file them as `research/answers-character-rounding.md` and cite it from E.13.

  - `sample.rs`'s `sample()` and its tests are left from the sample view; remove them and rename the module;

- **Font switcher panel** (rapid iteration, 13 October 2026, owner: "a separate fonts panel that lets me switch to any of those fonts … Bedstead must be the default"): Menu, "Switch font", a right-hand panel (`app/font_switcher.rs`) listing Bedstead first and then every library's fonts grouped by library; a click makes the font draw every set it conforms for and Bedstead the rest, or every set when it conforms for none (`Target::Switch`). The candidate fonts come from the two zips of built fonts in the collection, served as per-maker libraries `http://127.0.0.1:8642/manufacturers/<maker>/` generated from the tree by `tooling/pipelines/tree/make_maker_libraries.py` (14 October 2026; the earlier zip-based `candidates/` libraries were retired) added to this machine's settings by hand. Owed: a requirement and decision (it overlaps REQ-BRW-010's per-set choice); whether the panel is open is not saved; the up and down arrow keys step through Bedstead and every library's fonts and the page area shows the switched font's glyph table for a chosen set and its pair (owner: "arrow down through all the fonts and see the glyph table"), each step fetching the font the first time; `the_font_switcher_steps_with_the_arrow_keys` in `tests/window.rs` (with a second library, `/second/`, in `tests/web-server/sites.py`) covers clicking and stepping, including the bug fixed in rapid iteration: the switcher found the current font by SHA-256, so with the same font in two libraries (the seven recommended fonts are in the main library and the candidates) the arrow jumped to the entry after the font's first listing; it now steps by entry. It fails on the old matching. Owed: a test of the glyph table; the user guide; the 116 12 x 20 fonts of the two zips are not listed, pending the 12 x 20 decision; the panel was not seen open in a screenshot (the menu could not be clicked from a script: System Events timed out).
